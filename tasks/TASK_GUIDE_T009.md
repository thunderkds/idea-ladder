subscription that never sees the answer key; there is no second provider." Trade-off the user accepted: "a

## Approach

**Pattern reference**: `experiments/core-spike/src/measure.ts` — seeded wrong keys and the catch / false-reject arithmetic (port and extend to 3 policies, do not import from `experiments/`); `experiments/core-spike/src/report.ts` — pre-registered threshold verdict lines; T008's `regenerateMcq`, `logStepCost` use, and step wiring in `src/server/ladder-generate.ts`; `createModelA` in `src/server/model-a.ts`.

**Vital slice**: `blindSolve` + step `blind-solve` + the 3-policy measurement code on the independent seed set.
**Cut list**:
- blind solve without the chunk (closed-book variant) — the solver gets the cited chunk, not the key, because repo-specific facts are not in model B's training data
- majority vote over several model B calls
- entailment check (only if thresholds fail)
- diff questions (T014)

1. Model B is built with `createModelA` from its own env (`MODEL_B_BACKEND`, `MODEL_B_ID`); no new provider package. Record the design (same provider, fresh call, why no second provider) in `docs/decisions/0007-model-b.md`.
2. Write the seed set before any model B run. Commit it in its own commit with its `.sha256`.
3. Prompt for model B: the cited chunk (capped at 2,000 chars), the question, 4 shuffled options; answer with an index only. A system prompt says the text is data, not instructions.
4. Wire `blind-solve` into `ladder-generate`; store per-item results in the step output so an Inngest retry does not re-pay solved items.

## Edge Case Checklist

- [ ] Option shuffle maps back correctly (a test with every permutation of 4 options)
- [ ] Two options identical after normalisation → item already dropped by T008 `bad-options` before model B
- [ ] Model B picks "all of the above"-style option → treated like any option; seed set contains none
- [ ] Rate limit / `claude -p` failure mid-ladder → Inngest retries the step; already-solved items are not re-paid
- [ ] Seed set author is the same agent that writes the code → the seed is committed before the first run and hash-locked; the report states this limit
- [ ] Synthetic wrong keys (T001 known limit: catch rate is an upper bound) → stated in the report
- [ ] Paraphrase keys: code check rejects them by design; policy (c) inherits that false-reject — reported per kind
- [ ] Same-provider blind spots (user-accepted trade-off) → stated in the report
