## Approach

**Pattern reference**: `experiments/core-spike/src/measure.ts` — seeded wrong keys and the catch / false-reject arithmetic (port and extend to 3 policies); `experiments/core-spike/src/report.ts` — pre-registered threshold verdict lines; T008's regeneration loop and `logStepCost` use.

**Vital slice**: `blindSolve` + the 3-policy measurement on the independent seed set (the untested design choice).
**Cut list**:
- blind solve without the chunk (closed-book variant) — the solver gets the cited chunk, not the key, because repo-specific facts are not in model B's training data
- majority vote over several model B calls
- entailment check (only if thresholds fail)
- diff questions (T014)

1. Choose model B in the brainstorm. Criteria: a non-Anthropic provider with an AI SDK provider package; structured output support; price per 1M tokens; shortlist ≤ 2 candidates and measure both on the seed set, keep the one with the higher catch rate per dollar that meets the thresholds. Code names the model only through env `MODEL_B_PROVIDER` / `MODEL_B_ID`; no model id is hard-coded. If no candidate's API key is in env, stop with `Status: blocked` + `Question:` naming the provider(s) and the env key needed. Record the choice and its price source in `docs/decisions/0003-model-b.md`; add its price to `eval/prices.json`.
2. Write the seed set before any model B run. Commit it in its own commit; the measurement script refuses to run if the seed file changed after that commit (hash check against `eval/seed/blind-solver-seed.sha256`).
3. Prompt for model B: the cited chunk, the question, 4 shuffled options; answer with an index only. Cap the chunk at 2,000 chars.
4. Wire `blind-solve` into `ladder-generate`; regeneration reuses T008's generator for the one item.

## Edge Case Checklist

- [ ] Option shuffle maps back correctly (a test with every permutation of 4 options)
- [ ] Two options identical after normalisation → item dropped before model B is called (T008 `bad-options`)
- [ ] Model B picks "all of the above"-style option → treated like any option; seed set contains none
- [ ] Provider rate limit (429) mid-ladder → Inngest retries the step; already-solved items are not re-paid (store per-item results inside the step output)
- [ ] Seed set author is the same agent that writes the code → the seed is committed before the first run and hash-locked; the report states this limit
- [ ] Synthetic wrong keys (T001 known limit: catch rate is an upper bound) → stated in the report
- [ ] Paraphrase keys: code check rejects them by design; policy (c) inherits that false-reject — reported per kind
