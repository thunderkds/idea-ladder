# Run Idea Ladder on your machine

Goal: run the app locally. The models run on your Claude subscription. The database is a Railway Postgres.
Read "Keep the data safe" first.

## 1. Keep the data safe

- Make **one new database** for Idea Ladder on the Railway Postgres server, for example `idea_ladder`.
  Never use the database of another app (Idea Radar). Use only this one connection string.
- The first migration runs `CREATE EXTENSION IF NOT EXISTS vector` (`migrations/0001_init.up.sql`).
  Railway's default Postgres image has no pgvector. Use a Railway pgvector Postgres, or the extension is missing and `db:migrate` fails.
  Check first: in a SQL session on the new database, run `SELECT name FROM pg_available_extensions WHERE name = 'vector';`.
  No row means pgvector is not installed.
- **Never run the tests, `bun run ci:local` or `db:migrate:down` with the Railway `DATABASE_URL`.**
  - `ci:local` uses `DATABASE_URL` as an admin connection. It runs `DROP DATABASE IF EXISTS "il_ci"` and `CREATE DATABASE "il_ci"` on that server.
  - `db:migrate:down` drops tables. It needs `MIGRATE_ALLOW_DOWN=1`, so leave that unset.
  - Bun reads `.env` for `bun test` too. For tests, set the local value on the command line (see section 5).

## 2. One-time setup

1. Install Bun. Run `bun install --frozen-lockfile`.
2. Log in to the Claude CLI once: run `claude` and sign in with your subscription. Both models then use `claude -p`.
3. Create a fine-grained GitHub token with public read access only. This is `GITHUB_APP_TOKEN`.
4. Copy `.env.example` to `.env` (git ignores `.env`). Fill in the variables in section 3.
5. Optional: a GitHub OAuth app. You do not need it when you set `DEV_LOGIN_GITHUB_LOGIN` (section 3).
   To sign in through GitHub instead, create one (GitHub, Settings, Developer settings, OAuth Apps):
   - Homepage URL: `http://localhost:3000`
   - Callback URL: `http://localhost:3000/auth/github/callback`

## 3. Variables in `.env`

For local use, four variables are required: `DATABASE_URL`, `GITHUB_APP_TOKEN`, `SESSION_SECRET` and `DEV_LOGIN_GITHUB_LOGIN`.

| Variable | Value |
|---|---|
| `DATABASE_URL` | The Railway connection string of the new database. Required. |
| `GITHUB_APP_TOKEN` | The read-only token. Required. |
| `SESSION_SECRET` | A random string of at least 32 characters. Required. |
| `DEV_LOGIN_GITHUB_LOGIN` | Your GitHub username. The app signs you in as that account, with no OAuth app. It reads your numeric GitHub id with `GITHUB_APP_TOKEN`, so the L2/L4 author check works as usual. |
| `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET` | Optional. From the OAuth app. Required only when `DEV_LOGIN_GITHUB_LOGIN` is not set. When both are set, the dev login wins. |
| `MODEL_A_BACKEND`, `MODEL_B_BACKEND` | Leave unset. The default is `claude-code` (subscription). Do not set `api`. |
| `MODEL_A_ID`, `MODEL_B_ID` | Optional. A `--model` alias for the CLI. Unset means the CLI default. |
| `PORT` | Optional. Default 3000. Keep 3000 so it matches `inngest:dev` (and the OAuth callback URL, if you use one). |
| `START_MAX_NEW_JOBS_PER_HOUR` | Optional. Default 20 ladders per hour per learner. |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` | Optional. Set all three or none. None means review reminders are off. |

Do not set `NODE_ENV=production` locally. `bun run dev` sets `NODE_ENV=development`, so cookies work over plain `http`.

The dev login works only with `NODE_ENV=development`. With any other `NODE_ENV` (production, test or unset), the server refuses to start while `DEV_LOGIN_GITHUB_LOGIN` is set.
While it is set, any browser that can reach the port is signed in as you. So in dev login mode the server listens on `127.0.0.1` (localhost) only. Other machines cannot reach it.

## 4. Start the app

Run each command in its own terminal:

```bash
bun run db:migrate     # once, and again after you pull new migrations
bun run inngest:dev    # the job queue, at http://localhost:8288
bun run dev            # app at http://localhost:3000, rebuilds on change
```

Open `http://localhost:3000` and click `Sign in with GitHub`. With `DEV_LOGIN_GITHUB_LOGIN` set, you are signed in at once, with no GitHub page. Paste a public repo URL on the start page.
A ladder is generated by background jobs. Watch them at `http://localhost:8288`.

A ladder run uses your subscription allowance. A big repo uses more. Start with a small repo.

## 5. Run the tests (safe way)

Use the local Docker database, not Railway:

```bash
docker compose up -d db
DATABASE_URL=postgres://postgres:postgres@localhost:54329/idea_ladder bun test
DATABASE_URL=postgres://postgres:postgres@localhost:54329/idea_ladder bun run ci:local
```

Known: the full suite has flaky timeouts that also fail on the base commit (T015 offline-pack 5 s timeout, T008 step tests, T015 PWA Playwright specs). A red run there does not mean your change broke it.

## 6. What does not work locally yet

- No cost cap. `COST_CAP_USD_PER_LADDER` is not in `main` (T017 is deferred). A subscription run has no dollar price.
- No deploy (T018 is deferred).
- No live run of the L2 branch questions (T014) on a real repo has happened yet. Try it and tell us what breaks.
- Web Push needs HTTPS in most browsers. `localhost` is allowed.
